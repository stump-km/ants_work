# ants_work

用于推进 `bee-work` 愿景演进与新模块开发的独立工作仓；存量 `bee-work` 仓库保持不动，新代码与增量设计集中放在本仓库。

## 仓库分工与协同边界

* **存量基线（只读参考，不直接改动）**：`bee-work`（作为既有实现与愿景文档参考，避免在演进阶段破坏现有基线）。
* **新代码与愿景实现仓（本仓 `stump-km/ants_work`）**：承接 `bee-work` 愿景落地的增量代码、状态机与协议改造、测试验证与分步部署方案。
* **工作规划与挂载仓（`stump-km/work-mount`）**：存放 `pstack` / `poteto` 挂载清单、工作流阶段规划、跨仓协同契约与主机端执行记录，与代码实现解耦。

## 推进原则

1. **先理解与设计，后拆分为可验证单元**：先明确目标契约、边界与失败模式，再写代码与测试。
2. **基线冻结、增量演进**：不在存量基线上直接覆盖；新能力在 `ants_work` 中独立验证并形成可回滚的交付单元。
3. **验证与部署闭环**：所有涉及构建、测试、服务启停与服务器侧操作的步骤，均以本地/服务器真实执行输出作为完成依据。
